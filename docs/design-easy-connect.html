设计提案:免输入长网址连接

问题:现在要在 iPad 的 Safari 里手打 http://192.168.178.49:8800/?k=A9xQ2…,既长又容易输错,而且每次运行令牌都会变。

1. 问题根源

难点原因
IP 地址难记局域网 IP 由 DHCP 分配,会变
令牌很长令牌放在 URL 里,每次随机生成
每次都要重新输入没有“记住这台 iPad”的机制

2. 目标体验

第一次:iPad 相机扫一下终端里的二维码 → Safari 自动打开并配对 → 添加到主屏幕。
以后:在电脑上运行脚本,点主屏幕图标即可连接,一个字都不用输入。

A. 二维码(解决“输入长网址”)

  • 启动时在终端用 Unicode 方块字符画出二维码,内容是完整配对链接。
  • iPad 相机原生支持扫码,点一下就在 Safari 打开。
  • 实现:调用 qrencode -t UTF8(sudo apt install qrencode);没装时回退为只打印文字链接,并给出提示。

B. 固定且好记的地址:mDNS 主机名

  • Ubuntu 自带 Avahi,同一网络内 主机名.local 可直接解析,iPad 的 Safari 支持。
  • 地址变成 http://yang-macbookpro.local:8800,不再受 DHCP 影响。
  • 端口固定为 8800;如果想连端口都省掉,可选用 80 端口(需要 setcap 或端口转发,作为可选项,默认不开)。
  • 启动时自动读取 hostname,把 .local 地址和 IP 地址都打印出来(IP 作为备用)。

C. 配对 + Cookie(解决“令牌每次变化、每次要输”)

  • 二维码里的链接携带一次性配对令牌。服务器核对通过后,给这台 iPad 下发长期 Cookie(默认 90 天),并 302 跳转到不带令牌的干净地址。
  • 之后视频流、WebSocket 都用 Cookie 认证,URL 里不再出现令牌,主屏幕图标也不会失效。
  • 已配对设备保存在 ~/.config/ipad-display/devices.json(只存令牌哈希),重启脚本后无需重新配对。
  • 未配对的浏览器打开 .local 地址时,显示一个简洁的页面:输入终端上显示的 6 位数字 PIN(备用,不方便扫码时用)。PIN 比长令牌好输得多。
  • 新增 --forget 清除所有已配对设备,--no-pairing 仅限可信网络使用(跳过认证)。

D. USB 有线连接(可选的便利)

  • iPad 个人热点通过 USB 连接时,Ubuntu 一般拿到 172.20.10.x,iPad 在 172.20.10.1。脚本自动识别 ipheth 网卡并优先打印该网段的地址和二维码。

4. 不采用的方案

方案原因
短链接服务 / 云中转画面和控制权要经过第三方,违背局域网本地运行的初衷
原生 iPad App需要开发者账号和侧载,失去“无需安装”的优点
Bonjour 自动发现iOS Safari 不能浏览 Bonjour 服务,只能解析已知的 .local 名
关闭认证同一局域网任何人都能控制电脑,风险太高

5. 安全评估

  • 更好:令牌不再出现在会被历史记录、截图、分享的 URL 里;每台设备独立 Cookie,可单独撤销。
  • 一次性配对令牌:用过即失效,有效期 5 分钟;PIN 连续错误 5 次后锁定该来源。
  • 仍需注意:仍然是明文 HTTP,在不可信的 Wi-Fi 上请勿使用(Cookie 可被同网段嗅探)。建议在家庭网络或 USB 热点下使用,README 中明确说明。
