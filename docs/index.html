ipad-display-ubuntu

在 Ubuntu 22.04 (GNOME / Wayland) 上把 iPad 变成第二块显示器,类似 macOS 的 Sidecar。iPad 端只需要 Safari。

1. 它是怎么工作的

Wayland 下没有 xrandr 那种“虚拟输出”的办法,所以脚本直接向 GNOME 的合成器 Mutter 申请一块真正的虚拟显示器。GNOME 会把它当作普通屏幕:你可以把窗口拖过去,也可以在“设置 → 显示器”里调整位置、缩放。

  • 画面:PipeWire 拿到虚拟屏幕的画面,GStreamer 压成 JPEG,通过 multipart/x-mixed-replace 推给 Safari 的 <img>。
  • 分辨率:虚拟显示器的大小跟随请求的视频尺寸,所以可以直接设成 iPad 的 4:3(如 2048×1536)。
  • 触控:网页把手势翻译成 JSON,经 WebSocket 发回,脚本调用 NotifyPointerMotionAbsolute 等接口注入,不需要 uinput 或 root。
  • 依赖:仅 Python 标准库 + PyGObject/GStreamer,没有第三方 pip 包。

2. 安装与使用

sudo apt install python3-gi gir1.2-gst-plugins-base-1.0 python3-gst-1.0 \
  gstreamer1.0-pipewire gstreamer1.0-plugins-good gstreamer1.0-plugins-base qrencode
./ipad-display --position left
第一次(配对):用 iPad 相机扫终端里的二维码 → Safari 自动打开并配对 → 分享 → 添加到主屏幕。
以后:运行脚本,点主屏幕图标即可,不用输入任何东西。
  • 地址是固定的 http://主机名.local:8800(Ubuntu 自带 Avahi),不受 DHCP 变化影响。
  • 不方便扫码时,打开该地址并输入终端里的 6 位配对码。
  • 二维码和配对码一次性使用,用后自动更换;30 分钟没用也会更换。配对后的 iPad 记住 90 天。
  • 如果主屏幕图标要求输入配对码(iOS 主屏幕 App 的 Cookie 独立),按终端里的新码输入一次即可。
  • 想要不带端口的地址:sudo sysctl net.ipv4.ip_unprivileged_port_start=80,然后加 --port 80。
  • 管理设备:--list-devices 查看,--forget 全部取消配对。

5. 屏幕位置、黑边与性能

  • 位置:GNOME 42 的显示器设置不能拖动虚拟屏幕,请用 --position left 等参数。
  • 黑边:默认 --size auto,iPad 页面上报可视区域,脚本重建虚拟显示器使比例一致(旋转也会跟随)。请用主屏幕图标全屏打开。
  • 性能:帧率在 Mutter 一侧限流并在颜色转换前丢帧,触摸移动事件按帧合并,以免拖慢 gnome-shell。仍卡顿时降低 --max-edge / --fps。

5b. USB 有线连接(更低延迟)

用数据线连接 iPad,在 iPad 上开启“个人热点”。Ubuntu 会通过 ipheth 出现一个有线网络,脚本会自动识别 ipheth 网卡,优先打印并在二维码中使用该地址(通常是 172.20.10.x)。Wi-Fi 同样可用,只是延迟略高。

6. 安全与限制

  • 未配对的设备无法看到画面或控制电脑;配对需要一次性二维码或 6 位码,错 5 次锁定 5 分钟,每台设备独立 Cookie,记录在 ~/.config/ipad-display/devices.json(仅存哈希)。
  • 使用明文 HTTP,Cookie 在不可信 Wi-Fi 上可能被嗅探,请只在家庭网络或 USB 热点使用。
  • 依赖 Mutter 的私有 D-Bus 接口(org.gnome.Mutter.ScreenCast / RemoteDesktop),在 GNOME 42 上验证,其他版本可能失效。
  • 使用 MJPEG(本机没有 H.264 编码器),带宽比 H.264 高。
  • 暂不支持键盘透传、音频、Apple Pencil 压感。

7. 常见问题

没有出现虚拟显示器? 确认是 Wayland 会话:echo $XDG_SESSION_TYPE 应输出 wayland。

画面卡顿? 降低 --size、--quality 或改用 USB 连接。

字太小? 使用 --scale 2。
